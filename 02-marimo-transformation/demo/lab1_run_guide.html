From the project root, with the foundation on the path. The package lives under src/a2a_labs.

A · Run the REPL

This exercises the model selection (registry + WORM cascade), the settings toggle, and the request/response provenance — no network needed for the object demo.

$ PYTHONPATH=src python
# --- model selection through the governed cascade ---
>>> from a2a_labs import MODELS, ModelMessage
>>> class Pick:
...     @MODELS.guard
...     def select(self, vendor, model): return ModelMessage(vendor=vendor, model=model)
>>> m = Pick().select("Anthropic", "claude-opus-4-7")
>>> m.fabric_id, m.litellm
('Anthropic|claude-opus-4-7', 'anthropic/claude-opus-4-7')

# --- the wrong pair cannot be built (cascade rejects at the boundary) ---
>>> Pick().select("Anthropic", "openai/gpt-5")
ValueError: 'openai/gpt-5' is not a Anthropic model. ...

# --- request -> response provenance, BLAKE3-correlated ---
>>> from a2a_labs import WorkspaceState, ResponseStatus
>>> from a2a_labs.a2a_bridge import verify_correlation
>>> req = WorkspaceState(bgd_surrogate="BGD-1", fqdn="policy.aces.local",
...                     task_content="How much for therapy?")
>>> resp = req.respond(result="In-network: $25 copay.", status=ResponseStatus.OK)
>>> verify_correlation(req, resp)
True

# --- the settings toggle: one env var moves every agent ---
>>> from a2a_labs import Settings
>>> Settings(gemini_api_key="x").litellm_model(m.model if False else __import__("a2a_labs").VendorModel.GEMINI_PRO)
'gemini/gemini-3.1-pro-preview'
Note. The model-call cell (LiteLLM to Gemini) needs your key and network. The object cells above run offline — they demonstrate the governance layer, which is the point of Lab 1's refactor.

B · Run in Marimo

Marimo is reactive: change a cell and everything downstream re-runs. The notebook is the full lesson, not just the objects.

1

Launch the notebook

# edit mode (recommended for the lab)
uv run marimo edit marimo/lab1_basic_qa.py
# or read-only app mode
uv run marimo run marimo/lab1_basic_qa.py
2

Work through the cells

The notebook imports the same a2a_labs foundation, builds the PolicyAgent, and answers a coverage question against the policy PDF. Each cell is annotated.

Validate without launching: uv run marimo check marimo/lab1_basic_qa.py confirms the notebook is structurally sound — useful in continuous integration before a live run.

What you just ran

Both paths sit on the same foundation: closed-set Enumerations, a Pydantic Version 2 settings boundary, a model registry derived from fabric -L, the Write Once Reuse Many (WORM) cascade that validates a (vendor, model) pair before it can be constructed, and a request/response envelope correlated by BLAKE3 hash. Lab 2 takes these same objects onto a live Agent-to-Agent server.
